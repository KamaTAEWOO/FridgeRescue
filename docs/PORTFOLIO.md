# 냉장고 구조대 포트폴리오 사례

## 한 줄 요약

반복 입력 때문에 지속 사용하기 어려운 냉장고 관리 경험을, Android 공유·온디바이스 인식·검토 가능한 자동화로 다시 설계한 Compose 앱이다.

## 역할과 범위

- 제품 문제 정의와 예외처리 기준 수립
- Jetpack Compose 기반 Android 앱 설계·구현
- Room 데이터 모델, 알림 작업, OCR·공유·바코드 입력 파이프라인 구현
- 자동 테스트, 접근성, 하위 OS, 절전·재부팅, 릴리스·성능 QA
- 기획서, 테스트 케이스, QA 보고서와 데모 자료 작성

## 핵심 과제 1: 등록 비용을 줄이되 자동화를 맹신하지 않기

온라인 주문 텍스트, 이미지, PDF, 종이 영수증, 일반 바코드와 GS1 바코드를 하나의 후보 검토 흐름으로 모았다. 인식 결과는 곧바로 냉장고에 넣지 않는다. 식품 여부와 수량을 규칙으로 선별한 뒤 사용자가 선택·편집·확정하도록 해 자동화 오류를 되돌릴 수 있게 했다.

공유 원본은 앱 전용 캐시에 복사하고 초안 상태를 Room에 저장한다. 분석 중 프로세스가 종료돼도 재개할 수 있고, 실패한 파일이나 부분 OCR에서도 이미 찾은 후보와 직접 입력 경로를 보존한다.

## 핵심 과제 2: 날짜의 의미를 과장하지 않기

제조사가 표시한 날짜, 사용자가 직접 확정한 날짜, 보관 위치를 바탕으로 앱이 예상한 소비일을 별도 `FoodDateSource`로 모델링했다. 화면에서도 `제품 표시일`, `직접 확인한 날짜`, `앱 예상 소비일`을 다른 문구로 제공한다. 날짜가 없는 항목은 임의의 확정값을 만들지 않고 확인 필요 상태로 둔다.

## 핵심 과제 3: 상태 변경을 신뢰할 수 있게 만들기

먹음·아직 있음·일부 사용·버림을 이벤트로 기록하고 각 작업에 operation ID를 부여했다. 같은 알림 액션이 반복 전달돼도 한 번만 적용되며, 최신 작업은 스낵바에서 실행 취소할 수 있다. 리포트 역시 현재 행만 세지 않고 되돌림을 반영한 유효 이벤트를 집계한다.

## 핵심 과제 4: 백그라운드 제약 안에서 유용한 알림 만들기

WorkManager로 D-3, D-1, 당일 후보를 하루 한 번 요약한다. 조용한 시간에는 다음 허용 시간으로 미루며 알림 권한이 없어도 홈 임박 배지는 유지한다. 알림에서 먹음·아직 있음 행동을 바로 수행할 수 있고, 재부팅과 Doze에서 작업이 유실되거나 잘못 즉시 실행되지 않는지 확인했다.

## 아키텍처

```text
Compose UI
   ↓ action                 ↑ immutable state
ViewModel / UseCase / Flow
   ↓
Repository
   ├─ Room: 재료·행동·가져오기 초안
   ├─ DataStore: 알림 설정
   ├─ 앱 전용 캐시: 공유 파일
   └─ WorkManager: 만료 알림
```

UI는 이벤트를 `RescueAction`으로 전달하고 ViewModel이 단일 상태를 만든다. 날짜 추정, 구조 우선순위, 후보 저장, 중복 탐지, 알림 후보 계산을 별도 사용 사례로 분리해 JVM에서 빠르게 검증했다. Room과 Intent, Compose 상호작용은 계측 테스트로 보완했다.

홈은 임박 요약을 제목 아래 한 문장으로 줄이고 모든 등록 경로를 `재료 추가` 하나로 합쳤다. 재료 수와 검색·필터도 한 줄로 묶고 필터는 기본 접힘 상태로 두어 첫 화면에서 실제 재료 세 개까지 보이게 했다. 카드의 반복 배지는 문장형 메타데이터로 합치고 `관리`, `먹었어요` 두 행동만 노출했다. 하단 탐색은 중립 배경과 선택 탭 강조만 남겨 콘텐츠와 경쟁하지 않게 했다.

재료 추가 시트는 긴 안내와 세로 버튼 목록 대신 `영수증으로 한 번에`, `상품 하나씩` 두 그룹의 2×2 카드로 구성해 촬영·사진·바코드·직접 입력의 차이를 한 화면에서 비교할 수 있게 했다.

## 품질 전략

- 앱·서버 JVM 테스트 52개로 파서·정렬·중복·날짜·멱등성·리포트·서버 API·데모 픽스처 규칙 검증
- 계측 테스트 51개로 Room 마이그레이션·공유 Intent·Compose·카드 문구·접이식 필터·탭 탐색·가족 스냅샷 병합·데모 시드 멱등성 검증
- API 26/36 전체 테스트, 실제 TalkBack 서비스, 재부팅·Doze·절전 QA
- Release에서 R8·리소스 축소·외부 키 서명 및 APK/AAB 서명 검증
- 별도 Macrobenchmark 모듈과 앱 핵심 흐름 Baseline Profile 생성

## 성능 결과 해석

API 36 에뮬레이터 5회 참고 측정에서 Baseline Profile 적용 전후 콜드 스타트 중앙값은 286.7ms와 268.2ms였다. 약 6.5% 개선이지만 에뮬레이터 결과는 사용자 기기를 대표하지 않는다. 그래서 수치를 성과로 과장하지 않고, 실기기에서 같은 시나리오를 재실행할 수 있는 코드·명령·Perfetto trace 생성 경로를 함께 남겼다.

## 의도적으로 하지 않은 것

- 가격 근거가 없을 때 절약 금액을 추정하지 않았다.
- 이름이 같다는 이유만으로 재료 수량과 날짜를 자동 병합하지 않았다.
- 일반 바코드 숫자만 보고 상품명을 발명하지 않았다.
- 자동 인식 실패를 막다른 화면으로 만들지 않았다.

이 선택들은 기능 수보다 데이터 신뢰와 복구 가능성을 우선한 결과다.
