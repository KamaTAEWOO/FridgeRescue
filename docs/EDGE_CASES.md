# 냉장고 구조대 예외처리 기준

## 1. 불변조건

다음 조건은 UI, ViewModel, Repository, Worker 어디에서도 깨지면 안 된다.

```text
1. 사용자가 확인한 값은 OCR·자동 추정값보다 우선한다.
2. CONSUMED, DISCARDED, ARCHIVED 항목은 임박 목록과 향후 알림에서 제외한다.
3. 같은 operationId의 상태 변경은 한 번만 집계한다.
4. 예상 날짜와 제조사 표시 날짜를 구분한다.
5. quantity는 null이거나 0보다 큰 값이다.
6. 삭제 tombstone보다 오래된 수정은 항목을 복구하지 않는다.
7. 외부 URI와 원본 영수증은 보존기간을 넘겨 저장하지 않는다.
8. 앱은 식품의 안전 여부를 판정하지 않는다.
9. 알림을 열면 과거 payload가 아니라 현재 Room 상태를 사용한다.
10. 부분 성공 데이터를 실패와 함께 버리지 않는다.
```

## 14. MVP와 후속 범위

### MVP 필수

- 공유 URI·MIME·파일 크기 검증
- 부분 성공과 직접 입력 대체
- 예상 날짜·표시 날짜 구분
- 중복 후보와 일괄 확인
- 상태 변경 멱등성
- 소비 후 알림 취소
- 프로세스 종료 후 초안 복구
- 알림 권한 거부 대안
- 개인정보 제외와 임시 파일 삭제

### 후속

- 다중 파일 공유
- 가족 공유와 다중 기기 충돌
- 자동 저장 학습
- GS1 2D 날짜 인식 고도화
- 냉장고 사진 보조 점검
- 외부 식품 DB와 서버 동기화
