## 현재 제품 결정

1. 냉장고의 모든 재고를 정확히 관리하지 않는다.
2. 온라인 주문내역·전자영수증을 Android 공유 메뉴로 받는 방식을 기본 등록 경로로 사용한다.
3. 종이 영수증 촬영, 바코드, 직접 입력은 보조 경로다.
4. 채소·과일·유제품·육류처럼 폐기 위험이 높은 품목만 관리 후보로 선별한다.
5. MVP에서는 자동 선별 결과를 한 번에 확인하고 저장한다. 품목별 반복 입력은 요구하지 않는다.
6. 제조사가 표시한 날짜와 앱의 예상 소비일을 명확하게 구분한다.
7. Room을 단일 진실 공급원으로 사용하는 offline-first 앱으로 만든다.
8. 첫 출시 범위는 개인 냉장고다. 가족 공유와 서버 동기화는 후속 범위다.
9. 레시피 추천보다 `오늘 먼저 먹을 재료`와 `먹었어요` 행동을 우선한다.
10. 폐기 기록을 실패나 비난으로 표현하지 않는다.

## 문서 운영 규칙

- 구현 중 제품 결정이 바뀌면 관련 문서를 코드보다 먼저 수정한다.
- 기능 구현과 관련 자동 테스트는 같은 작업 단위에서 작성한다.
- 요구사항은 `FR-영역-번호`, 예외는 `영역-번호` 형식으로 추적한다.
- 날짜, 수량, 상태 전이 규칙은 UI와 데이터 계층에서 동일한 용어를 사용한다.
- MVP와 출시 후 범위를 섞지 않는다.
- 기술 버전은 Gradle Version Catalog를 기준으로 하고 문서에는 역할과 선택 이유를 기록한다.
